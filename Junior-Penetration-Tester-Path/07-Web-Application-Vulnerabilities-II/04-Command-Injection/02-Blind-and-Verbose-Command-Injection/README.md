# Blind & Verbose Command Injection

## Overview

Command Injection vulnerabilities are commonly identified through the way an application responds after malicious input is submitted. Some applications immediately display the output of executed commands, while others execute commands silently without returning any visible feedback. These behaviours are commonly referred to as **Verbose Command Injection** and **Blind Command Injection**.

This lesson explains both techniques, demonstrates how they can be detected, introduces common payloads used during assessments, and highlights the differences between Linux and Windows environments. :contentReference[oaicite:0]{index=0}

## Main Content

### Blind Command Injection

Blind Command Injection occurs when injected commands execute successfully, but the application does not display their output.

Instead of relying on visible results, testers observe changes in application behaviour to determine whether the payload executed.

Common indicators include:

- Delayed responses
- Time-based behaviour
- Changes to application functionality
- Files created on the server

Because no direct output is available, Blind Command Injection often requires additional experimentation. :contentReference[oaicite:1]{index=1}

---

### Verbose Command Injection

Verbose Command Injection occurs when the application directly displays the output generated by executed commands.

Examples include displaying the output of commands such as:

- `whoami`
- `ls`
- `dir`

This makes vulnerability identification significantly easier because the application immediately reveals the command results. :contentReference[oaicite:2]{index=2}

---

### Common Detection Payloads

Different operating systems provide different commands for testing.

**Linux examples:**

- `whoami`
- `ls`
- `ping`
- `sleep`
- `nc`

**Windows examples:**

- `whoami`
- `dir`
- `ping`
- `timeout`

Time-based commands such as `ping`, `sleep`, and `timeout` are particularly useful when testing Blind Command Injection because they create observable delays in application responses. :contentReference[oaicite:3]{index=3}

---

### Choosing a Testing Strategy

The testing approach depends on the application's behaviour.

When output is visible:

- Observe command results directly.
- Confirm operating system command execution.

When output is hidden:

- Use time-based payloads.
- Observe behavioural changes.
- Look for indirect evidence that commands executed successfully.

Understanding the application's response helps determine the most effective testing methodology.

# Introduction

## Overview

Cross-Site Request Forgery (CSRF) is a web application vulnerability that abuses a user's authenticated session to perform actions without their knowledge or consent. Because browsers automatically include session credentials with requests, attackers may exploit this behaviour to trigger unwanted operations on trusted websites.

This lesson introduces the fundamental concepts of CSRF, explains why it remains an important web security issue, and prepares you for understanding how these attacks are identified and prevented.

---

## Learning Objectives

After completing this lesson, you should be able to:

- Define Cross-Site Request Forgery (CSRF)
- Understand the relationship between authenticated sessions and CSRF attacks
- Explain the potential impact of forged requests
- Recognise why CSRF remains relevant in modern web applications
- Understand the importance of secure request validation

## Main Content

### What Is CSRF?

Cross-Site Request Forgery is a vulnerability that allows an attacker to cause a victim's browser to send unintended requests to a web application where the victim is already authenticated.

Because the request originates from the victim's browser, the application may treat it as a legitimate action.

---

### Why It Matters

Successful CSRF attacks can affect both users and organisations by causing unintended actions to be performed under a legitimate user's identity.

Possible impacts include:

- Unauthorised account changes
- Unintended data modifications
- Execution of sensitive application functions
- Abuse of authenticated user privileges
- Loss of data integrity

---

### Authentication and Trust

Web applications often trust requests that include valid session credentials.

Without additional verification mechanisms, an application may be unable to distinguish between a legitimate user action and a forged request generated by an attacker.

---

### Understanding the Risk

Unlike many other web vulnerabilities, CSRF does not rely on stealing authentication credentials.

Instead, it abuses the trust established by an existing authenticated session, making secure request validation an essential part of application security.

## Key Takeaways

- CSRF exploits authenticated user sessions rather than authentication credentials themselves.
- Browsers automatically sending session information can create security risks if requests are not properly validated.
- Applications should verify that sensitive requests originate from legitimate user actions.
- Understanding the fundamentals of CSRF provides the foundation for identifying and preventing these attacks.

# 05 - DevSecOps: Security Shifts Left

## Overview

DevSecOps integrates security into DevOps as a shared responsibility.

It relies heavily on:

    Automation
    Platform Design
    Collaboration
    Shared Responsibility
    Security Culture

Security becomes a normal part of day-to-day development.

---

## Value of DevSecOps

DevSecOps can:

    Reduce Vulnerabilities
    Increase Test Coverage
    Automate Security Frameworks
    Reduce Risk
    Improve Auditing
    Improve Monitoring

This can help organisations reduce the potential impact of security incidents.

---

## Culture Is Key

DevSecOps requires:

    Open Communication
    Trust
    Collective Effort
    Shared Security Responsibility

Security knowledge should not remain isolated within a specialised security team.

Teams need the tools and knowledge required to make secure decisions independently.

---

# DevSecOps Challenges

## 1. Security Silos

Security teams can sometimes become separated from DevOps processes.

This creates a security silo where only specialised security personnel are expected to handle security.

Consequences include:

    Limited Collaboration
    Limited Security Knowledge
    Security Introduced Too Late
    Security Becoming a Blocker

Security should instead support teams and help them build secure solutions.

---

## 2. Lack of Visibility & Prioritisation

Security should be treated as a normal part of the application.

Teams need visibility into the security state of the services they own.

Without visibility:

    Findings
        ↓
    Backlog
        ↓
    Noise
        ↓
    Poor Prioritisation

Security information should help teams understand which risks require attention and when.

---

## 3. Stringent Processes

Overly complicated security processes can slow development.

Not every change should require the same level of security review.

A better approach is to apply stronger controls to:

    Higher-Risk Changes
    Sensitive Systems
    Important Security Decisions

while allowing lower-risk experimentation to move faster.

---

## Sandboxes

Developers may need environments where they can safely experiment.

A sandbox is a temporarily isolated environment.

The room describes these environments as having:

    No Internal Network Connection
    No Customer Data

This allows experimentation without exposing production resources.

---

## Key Takeaways

- DevSecOps makes security a shared responsibility.
- Automation helps integrate security into development.
- Culture and communication are essential.
- Security Silos isolate security from development.
- Lack of Visibility makes risk prioritisation difficult.
- Stringent Processes can unnecessarily slow development.
- Sandboxes provide isolated environments for experimentation.

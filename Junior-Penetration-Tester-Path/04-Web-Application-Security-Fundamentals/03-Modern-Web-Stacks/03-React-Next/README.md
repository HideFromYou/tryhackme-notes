# React & Next.js

## Overview

Next.js is one of the most popular frameworks built on React for developing modern web applications. It introduces server-side rendering, middleware, routing, and React Server Components, creating a different attack surface compared to traditional client-side React applications.

Understanding how to fingerprint Next.js applications allows penetration testers to identify framework-specific behaviour and determine whether known vulnerabilities may apply.

---

## Learning Objectives

- Understand the purpose of Next.js
- Identify Next.js applications
- Recognise framework-specific indicators
- Understand middleware behaviour
- Learn how fingerprinting supports vulnerability research

---

## What is Next.js?

Next.js extends React by providing features such as:

- Server-side rendering (SSR)
- Static site generation
- App Router
- API routes
- Middleware
- React Server Components

These capabilities improve performance while introducing additional server-side functionality.

---

## Fingerprinting Next.js

Common indicators include:

- `X-Powered-By: Next.js`
- `/_next/` static resources
- Next.js response headers
- Middleware-related headers
- HTML artifacts generated by the framework

Combining multiple indicators increases confidence when identifying the framework.

---

## React Server Components

Modern versions of Next.js execute components directly on the server before delivering rendered content to the browser.

This approach:

- Reduces client-side processing
- Improves performance
- Changes application architecture
- Introduces new server-side attack surfaces

Understanding this architecture helps analysts interpret application behaviour.

---

## Middleware

Middleware processes requests before they reach the application's routes.

Typical responsibilities include:

- Authentication
- Authorization
- Request filtering
- Redirects
- Session validation

Because middleware often enforces security controls, understanding its behaviour is essential during reconnaissance.

---

## Framework Identification

When fingerprinting Next.js applications, analysts should verify:

- Framework indicators
- Deployment mode
- Routing behaviour
- Server responses
- Available headers

This information supports version research and vulnerability validation.
